# Cthulhu Handbook Design

## 1. 背景与目标

当前 `readme.md` 已积累大量内容，但存在单文件过长、分类 schema 不统一、贡献门槛高的问题。本设计文档用于定义 handbook 的长期信息架构、内容标准与治理机制，为后续分步实施提供稳定蓝图。

本项目定位为“克苏鲁神话入门与文学体验手册”，而非严谨规则书或全量 Wiki。

### 1.1 设计目标

- 统一：不同类型条目使用一致的核心字段，降低维护成本。
- 可扩展：从单文件演进为多文档结构，支持持续新增条目。
- 可协作：明确贡献流程、来源标准和审阅规则。
- 可检索：提供目录、索引、交叉引用，提升查阅效率。
- 可验证：通过文档规范与自动校验减少格式漂移。
- 可感知：在条目中保留文学性入口（经典片段、故事脉络、二创路径），帮助读者建立直观印象。

### 1.2 非目标

- 不在第一阶段一次性补齐所有神话条目。
- 不追求复杂静态站点化（先保证 Markdown 可维护）。
- 不以“规则完备度”作为主要目标，不追求百科全覆盖。

## 3. 条目 Schema 设计

## 3.1 核心字段（所有实体类条目共用）

- 名称（中文 / English）
- 分类（如外神、独立种族、地点）
- 理智损失（如适用）
- 别名/称号
- 简介
- 关键特征（形态/化身/能力）
- 遭遇或召唤条件
- 关联势力
- 出现作品
- 经典片段摘录（原文/公版译文，附来源）
- 经典故事脉络（1-3 段，强调阅读顺序与核心冲突）
- 常见二创路径（影视/游戏/TRPG/视觉符号等）
- 相关条目（交叉引用）
- 参考来源（原典/扩展设定）

## 3.2 分类扩展字段

- 神祇：化身、影响方式、禁忌仪式风险。
- 生物：生态位、行为模式、可控性风险。
- 地点：调查钩子、进入条件、危险评级。
- 典籍：获取方式、阅读代价、关键知识点。
- 遗物：效果、代价、封印/销毁方式。
- 仪式：前置条件、流程、失败后果。

文学性扩展建议（跨分类通用）：

- “初识入口”：一句话解释为什么这个条目值得读。
- “经典片段摘录”：优先引用公版或可引用文本，控制在短摘录。
- “二创观察”：总结常见改编母题与误读点。

## 4. 编辑与风格规范

## 4.1 命名规范

- 条目标题统一为 `中文名 (English Name)`。
- 英文专有名词使用主流译名；如存在歧义，在条目内说明别名。

## 4.2 文风规范

- 保持百科式、说明式语气，避免第一人称和剧情化描述。
- 事实与设定分离：原典优先，扩展设定需标注来源。
- 在“经典片段摘录/故事脉络”模块允许更具文学性的表达，但需避免无来源演绎。

## 4.3 引用规范

- 作品引用格式：`《中文名》 (English Title, Author)`。
- 来源至少区分：原典（Lovecraft/Chambers/Smith 等）与后世扩展。
- 片段摘录必须标注出处；若为意译/转述，需显式标注“转述”。

## 4.5 证据分级与索引要求

- A 级（原典直接证据）：原文段落、章节、可核验版本信息。
- B 级（权威二手资料）：公认研究资料、官方出版注释、成熟规则书条目。
- C 级（社区归纳）：论坛/二创社区总结，仅作补充，不得覆盖 A/B 级结论。

落库要求：

- “经典片段摘录”至少达到 A 或 B 级证据。
- “经典故事脉络”必须给出最少 1 条 A/B 级来源。
- “规则相关内容”必须标注版本与页码/章节，不接受“常识写法”。
- 禁止无来源断言与凭空想象；无法确认时使用“待考”标签并列出待核来源。

## 4.4 理智损失说明

- 统一在总览页提供 SAN 记法说明（例如“初见/深入接触”）。
- 条目中保持同一种记法，不混用不解释的变体。

## 5. 交叉引用与索引

## 5.1 交叉引用规则

- 每个条目至少包含 2 个“相关条目”。
- 关联关系应双向可追溯（A 指向 B 时，B 的相关条目中也应出现 A）。

## 5.2 索引设计

- 中文拼音索引。
- 英文首字母索引。
- 分类索引（神祇/生物/地点/典籍/遗物/仪式）。

## 6. 质量门禁

## 6.1 人工审阅清单

- 字段完整性：必填字段是否齐全。
- 风格一致性：标题层级、列表风格、引用格式是否统一。
- 内容正确性：是否混淆原典和扩展设定。
- 交叉引用：是否存在孤立条目。
- 文学模块质量：摘录是否有来源、故事脉络是否清晰、二创总结是否避免空泛。

## 6.2 自动校验建议

- Markdown lint：校验标题层级、空行、列表格式。
- 结构校验脚本：检查每个条目是否包含必填标题块。

## 7. 迁移策略

- 第一步：先建立目录与模板，不大规模改写内容。
- 第二步：按类别迁移（神祇 -> 生物 -> 地点）。
- 第三步：补齐缺失章节（典籍/遗物/仪式）。
- 第四步：完善索引、术语表、贡献文档与变更记录。

## 8. 验收标准

- `readme.md` 成为清晰入口页并链接到新目录。
- `docs/handbook/` 六大域至少各有 index。
- 新增或迁移条目符合统一 schema。
- 贡献者可仅凭 `CONTRIBUTING.md + style-guide.md` 独立提交合格条目。
