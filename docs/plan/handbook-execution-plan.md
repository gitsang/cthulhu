# Handbook Execution Plan

## 0. 执行原则

- 小步快跑：每一步都可独立审阅与回滚。
- 先结构后内容：先统一标准和目录，再大规模扩写。
- 原典优先：优先保证核心来源一致性，再补扩展设定。
- 每阶段有明确产出、验收标准和风险控制。
- 产品定位：面向“克苏鲁神话入门与文学体验”，不走规则书/百科全覆盖路线。
- 严谨底线：故事、摘录、规则内容均需可追溯证据，禁止无来源创作性断言。

## 1. 里程碑总览

| 里程碑 | 目标 | 产出 | 预计工作量 |
|---|---|---|---|
| M1 | 建立文档工程骨架 | docs 目录、设计文档、执行计划 | 0.5 天 |
| M2 | 完成规范与贡献机制 | style-guide、CONTRIBUTING、CHANGELOG | 1 天 |
| M3 | 完成内容拆分迁移（首轮） | gods/creatures/locations 三大域拆分 | 1-2 天 |
| M4 | 补齐核心缺失域 | tomes/artifacts/rituals 初版内容 | 2-3 天 |
| M5 | 文学性增强首轮 | 经典片段/故事脉络/二创路径模块 | 1-2 天 |
| M6 | 建立检索与质量门禁 | 索引页、交叉引用、lint/结构检查 | 1-2 天 |

## 2. 分阶段执行

## Phase A（当前阶段）：设计与计划落盘

### 目标

将“怎么做”写清楚，作为后续执行唯一基线。

### 任务

1. 新建 `docs/design/handbook-design.md`。
2. 新建 `docs/plan/handbook-execution-plan.md`。
3. 确认两份文档可读且路径清晰。

### 验收标准

- 设计文档覆盖：信息架构、schema、风格规范、质量门禁、迁移策略。
- 执行计划覆盖：阶段拆分、任务清单、验收标准、风险与缓解。

## Phase B：规范与协作机制（下一步优先）

### 目标

让后续新增条目遵循统一标准，避免继续漂移。

### 任务

1. 从 `docs/design/handbook-design.md` 第 4 章抽取并固化为 `docs/style-guide.md`（命名、术语、引用、SAN 记法），避免重复维护。
2. 新建 `CONTRIBUTING.md`（提交流程、模板、审阅清单）。
3. 新建 `CHANGELOG.md`（变更记录规则与首版条目）。

### 验收标准

- 贡献者可按模板写出完整条目。
- 审阅者可按清单进行一致性检查。

## Phase C：内容拆分迁移（神祇/生物/地点）

### 目标

把 `readme.md` 的大段正文拆到分类文档，降低后续编辑冲突。

### 任务

1. 建立 `docs/handbook/index.md` 与三大域 `index.md`。
2. 迁移神祇内容到 `docs/handbook/gods/*.md`。
3. 迁移生物内容到 `docs/handbook/creatures/*.md`。
4. 迁移地点内容到 `docs/handbook/locations/*.md`。
5. 为已迁移条目补齐缺失 schema 字段（至少包含“相关条目”“参考来源”）。
6. 统一字段别名（如“别称”与“别名/称号”），并在迁移日志中记录映射规则。
7. `readme.md` 改为入口导航，保留简短示例内容。

### 验收标准

- 三大域都有独立文件和目录索引，且每个域至少迁移 10 个条目。
- 已迁移条目中，至少 80% 具备“相关条目”字段且每条至少 2 个交叉引用。
- 已迁移条目中，至少 80% 具备“参考来源”字段（区分原典/扩展）。
- 原 `readme.md` 无大段重复正文，仅保留导航与说明。

## Phase D：补齐缺失域（典籍/遗物/仪式）

### 目标

补齐 handbook 的核心知识面，达到“可用完整版”。

### 任务

1. 新建 `docs/handbook/tomes/index.md` 并录入首批条目。
2. 新建 `docs/handbook/artifacts/index.md` 并录入首批条目。
3. 新建 `docs/handbook/rituals/index.md` 并录入首批条目。
4. 每个条目补充“相关条目”和“参考来源”。

### 验收标准

- 三个新域各至少有 5 个结构化条目。
- 条目字段满足统一 schema。

## Phase E：文学性增强首轮

### 目标

把 handbook 从“资料清单”提升为“可读的神话入口”，增强文学体验与理解引导。

### 任务

1. 为优先条目补充“经典片段摘录”模块（至少 10 条）。
2. 为优先条目补充“经典故事脉络”模块（至少 10 条）。
3. 为优先条目补充“常见二创路径”模块（至少 10 条）。
4. 对新增文学模块统一补齐来源标注。
5. 对规则相关内容补齐版本与章节/页码索引。

### 验收标准

- 三个文学模块均已有可复用示例。
- 至少 10 个核心条目具备完整文学模块。
- 摘录模块来源标注覆盖率达到 100%。
- 规则相关条目中，版本与章节/页码索引覆盖率达到 100%。

## Phase F：检索能力与质量门禁

### 目标

提高查阅效率并减少格式回归。

### 任务

1. 建立索引页（中文/英文/分类）。
2. 补全关键条目的双向交叉引用。
3. 引入 Markdown lint（或等效检查流程）。
4. 增加结构校验脚本（检查必填标题块）。

### 验收标准

- 任一条目可在 3 次点击（总览 -> 分类 -> 条目）内定位。
- 新增条目可被自动规则检查。

## 3. 执行顺序（建议）

1. 先完成 Phase B（规范）再做 Phase C（迁移）。
2. Phase C 与 Phase D 可交错推进，但每次只处理一个域。
3. Phase E 在三大域首轮迁移后尽快接入。
4. Phase F 在 Phase E 后执行，保证文学增强不破坏结构一致性。

## 4. 任务粒度与提交策略

- 单次改动尽量控制在一个子域内，避免大规模混改。
- 每次提交只做一类事情：结构搭建 / 迁移 / 新增条目 / 质量规则。
- 迁移优先不改语义；若需补字段，仅补结构字段（相关条目/参考来源/分类），不重写设定结论。
- 每次迁移前创建基线备份文件（例如 `readme.md.backup` 或分段快照）以支持快速回滚。

## 5. 风险与缓解

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| schema 再次漂移 | 多人编辑导致字段不一致 | 先完成 style-guide 与模板，审阅时卡字段完整性 |
| 引用来源混杂 | 原典与扩展设定混写 | 强制“参考来源”字段，并区分原典/扩展 |
| 摘录或故事失真 | 文学增强时出现无依据内容 | 强制 A/B 级证据门槛，无法确认时标注“待考” |
| 规则信息误导 | 未标版本导致规则冲突 | 规则内容强制写版本+章节/页码，审阅时优先拦截 |
| readme 入口失焦 | 拆分后导航不清晰 | 保持 readme 为单一入口，维护稳定目录 |
| 后续维护疲劳 | 条目增长后审阅成本上升 | 自动化 lint + 结构校验，降低人工负担 |
| 迁移失败难回退 | 批量改动后难定位问题 | 迁移前做快照备份，按子域小步提交，失败时按最近快照回滚 |

## 6. 下一步（从现在开始）

执行顺序建议：

1. 创建 `docs/style-guide.md`（先锁定写法）。
2. 创建 `CONTRIBUTING.md`（让协作可持续）。
3. 建立 `docs/handbook/index.md` 和三大域 `index.md`（开启迁移入口）。

完成以上三步后，即可按域分批迁移现有内容并开始补齐缺失域。
